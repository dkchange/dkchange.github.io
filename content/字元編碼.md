# 前言

平常在 coding 的我們，最常接觸的東西就是打字，每一種編碼標準都是為了轉換 byte value 與 character，使用不同的編碼方式，同一個二進制數字可以被解釋成不同的符號。

每一種特定的語言，都存在一種或數種的字元集，每一種字元集就是一個代碼頁（[[Code Page]]）。例如：[[Big5]] 的 Code Page = 950。

> 參考：[[字符編碼筆記]]、[[ASCII、Unicode 和 UTF-8]]

# Unicode

但傳統編碼無法在同一個檔案裡面同時支援多個語系。Unicode 是為了解決傳統的字元編碼方案的侷限所產生的一項業界標準，它只規定了符號的二進制代碼，卻沒有規定這個二進制代碼應該如何儲存。

## 為何用 16 進制？

因為用二進制來對應所有的字實在太長。漢字「嚴」的 Unicode 是十六進制數 4E25，轉換成二進制數足足有 15 位（100111000100101），所以 Unicode 採用 16 進制來做對應。

Unicode 當然是一個很大的集合，現在的規模可以容納 100 多萬個符號。你覺得字元要用多少 bit 才夠，如何有辦法對應所有的語言的字母？
大概 2 的 21 次方就可以容納 1,999,999 個字，也就是 2 bytes 到 3 bytes 之間。

`\u4e2d\u6587` 這是中文兩個字所對應的 Unicode。

## Unicode 衍生出的編碼方式

常見的 Unicode 編碼方式有 [[UTF-8]]、UTF-16、UTF-32，詳細可參考 [Unicode 轉換器](https://www.branah.com/unicode-converter)。

### UTF-8

UTF-8 是 Unicode 的實現方式之一，最大的特點是它是一種變長的編碼方式，可以使用 1~4 個位元組表示一個符號。

`\xE4\xB8\xAD\xE6\x96\x87` 這是中文兩個字所對應的 UTF-8。

### UTF-16

UTF-16 是 Unicode 的實現方式之一，字元用兩個位元組或四個位元組表示。

`\u{4e2d}\u{6587}` 這是中文兩個字所對應的 UTF-16。

### UTF-32

UTF-32 是 Unicode 的實現方式之一，字元用四個位元組表示。

那由以上來看，UTF-8 要比其他兩種方式都省空間。`U+00004e2dU+00006587` 這是中文兩個字所對應的 UTF-16。

# 相關技巧

## 16 進位的轉換

假設你有一個 string `str="12345"`，你想加一個字元 enter，它的 16 進位編碼是 0A。`"\x31\x32\x33\x34\x35\x0A"` 貼在瀏覽器會變成：

```js
"x312345
"
```

## 查看檔案編碼

```bash
$ od -xc "filename" | head
```

參數說明：

- `a`：利用預設的字元來輸出
- `c`：使用 ASCII 字元來輸出
- `d[size]`：利用十進位 (decimal) 來輸出資料，每個整數佔用 size bytes
- `f[size]`：利用浮點數值 (floating) 來輸出資料，每個數佔用 size bytes
- `o[size]`：利用八進位 (octal) 來輸出資料，每個整數佔用 size bytes
- `x[size]`：利用十六進位 (hexadecimal) 來輸出資料，每個整數佔用 size bytes

## 亂碼轉換

在 UTF-8 還沒普及之前，大家都習慣有各自語言的編碼，例如 [[Big5]] 和 GBK。所以當你切換編碼時，編輯器在顯示時就會出現亂碼，此時你又按下了儲存鍵，這樣原本的 GBK 編碼的內容就會流失，要還原可能只能還原一部分了....
